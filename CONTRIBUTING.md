# Как мы работаем

## Ветки

- В `main` напрямую не пишем, каждая задача делается в своей ветке. 
- Формат названия: `<тип>/<номер issue>-<коротко>`, латиницей, маленькими буквами, через дефис.
- Типы: `feat` — новая функция, `fix` — исправление, `docs` — документация, `test` — тесты, `ci` — CI и сборка, `refactor` — переделка без изменения поведения.
- Примеры: `docs/1-readme`, `feat/3-match-list`, `fix/9-duplicate-matches`.

## Коммиты

- Формат: `<тип>: <что сделано>`, например `feat: добавить список матчей за диапазон дат`.
- Один коммит — одно изменение.
- Сообщения вроде «правки» и «update» не используем.

## Review

- Изменения попадают в `main` только через Pull Request.
- В описании PR указываем задачу: `Closes #<номер issue>`.
- PR одобряет хотя бы один другой участник команды; одобрять свой PR нельзя.
- Замечания автор исправляет, после чего PR проверяется снова.
- Сливает PR автор после одобрения.
- Срок review — не больше 4 дней.

## Definition of Done

Задача считается сделанной, когда:

- [ ] PR связан с issue (`Closes #N`);
- [ ] PR одобрен хотя бы одним другим участником;
- [ ] CI проходит успешно (после настройки CI);
- [ ] для новой логики есть тесты, критерии приёмки сценария выполнены;
- [ ] токены и пароли не попали в репозиторий, новые настройки добавлены в `.env.example`;
- [ ] при изменении структуры базы добавлена миграция;
- [ ] README и `docs/requirements.md` обновлены, если поменялось поведение;
- [ ] PR слит в `main`, issue закрыт.
